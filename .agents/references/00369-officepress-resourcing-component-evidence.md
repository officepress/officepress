## Workflow definitions and automation versions — Q-008 / G-11

[Workflow publication implementation](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow/domain/definition-transaction.ts#L285) is now an editable shared-definition model. `publishDraft` checks the expected revision, normalizes and validates the draft, reuses `flow.currentDefinitionId` when present, and updates that definition and its stages. Existing stages cannot simply disappear: missing stable stages return `STAGE_REMOVAL_UNSUPPORTED`. Where multiple old published definitions exist, an explicit conversion path may run and require stage mapping. Updating the current definition increments its revision while retaining its definition ID and existing version. Cards therefore do not receive immutable per-publication workflow snapshots merely because a field is named `version`.

[Run definition checks](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow/domain/run-transaction.ts#L295) requires a published current definition and matching expected definition ID/version when starting work. [Shared board projection](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow/domain/projection.ts#L410) explicitly uses the shared editable configuration. This conflicts with copying that implementation unchanged under D-15. The accepted immutable proof rule remains authoritative; do not quietly replace it with the live application's editable semantics.

Automation execution is a different responsibility. [Automation revision lookup](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow-automation/domain/runtime.ts#L416) loads `WorkflowAutomationRevision` by `run.revisionId`, fails permanently if unavailable, and skips successful action checkpoints keyed by run and action position. This is a useful retained-revision/checkpoint candidate. It does not make the separate workflow stage definition immutable.

## Elapsed time and stale writes — Q-010 / Q-012

[Workflow time-state calculation](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow/domain/projection.ts#L540) divides the difference between current time and stage entry by 3,600,000; the card approaches its target at 80% and is overdue at the target. [Automation target deadline](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow-automation/domain/runtime.ts#L734) derives approaching/missed deadlines from event time plus target hours, optionally subtracting lead minutes. These paths implement elapsed time, with no business-hours calendar in the calculation.

[Guarded workflow movement](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workflow/domain/movement-transaction.ts#L75) runs in a transaction, replays prior matching request IDs, rejects missing expected revision/stage for arbitrary workflows, and returns 409 `WORKFLOW_STALE_CARD` when the expected revision or source stage differs. Publication likewise returns `WORKFLOW_STALE`. This establishes the stale-save rejection policy; atomic race behavior in the adopted implementation still needs its own database proof.

## Message definitions, rendered evidence and uncertain delivery — Q-008 / Q-009

[Message version activation](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/messages/domain/persistence.ts#L670) checks `expectedRevision`, validates the draft and sender readiness, marks the prior active version `SUPERSEDED`, activates the new draft and changes the message pointer. An enabled automation dependency can block an incompatible activation. [Persisted delivery evidence](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/messages/domain/persistence.ts#L1008) encrypts the destination/rendered content/values and records a content digest, resolved snapshot, `versionId`, request ID and optional resend lineage on the attempt. Retention dates are recorded separately; the proof must not confuse version retention with unlimited sensitive-payload retention.

[Durable delivery selection and outcomes](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/messages/domain/delivery.ts#L58) selects due `PENDING`/`FAILED` outboxes and expired `CLAIMED` leases. It claims with compare-and-set, selects MTP email or Twilio SMS adapters, records provider correlation, and records provider states. An explicit `UNKNOWN` result completes the outbox as `UNKNOWN`; an unexpected exception does the same. These terminal unknown rows are not selected by the ordinary due-work filter.

There is an important recovery qualification: an expired `CLAIMED` personnel-form attempt becomes `UNKNOWN`, but other expired claimed rows become `FAILED` and can be claimed again. Rate-limit handling has a bounded backoff branch; the normal filter also includes `FAILED`, so this is not a universal no-resend guarantee. Review each error/recovery branch before adoption. [Message worker retry configuration](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/messages/domain/inngest.ts#L79) sets dispatch `retries: 0`, but that does not disable the separate durable outbox recovery path. The in-memory [Runtime transition helper](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/messages/domain/runtime.ts#L388) sets `automaticRetryAllowed=false` for `UNKNOWN`; it must not be mistaken for proof that every persistent crash path behaves identically.

Q-009 therefore has useful source precedent for unknown-state handling, with a lease-recovery exception. Live email here uses an MTP adapter; it does not satisfy the proof suite's separately accepted real SMTP requirement merely by existing.

## Forms are an application composition over a provider — Q-007 / Q-007a / G-15

[Forms provider client](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/forms/domain/client.ts#L6) sends bounded authenticated POSTs to a fixed configured origin, disallows redirects, times out, bounds response bytes and categorizes 409/400/401/403/404 and unavailable responses. [Forms connection configuration](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/config/forms.ts#L1) supplies origin/application identity/secret/source/receiver on the server. The read/command endpoints are `/api/forms/experience/read` and `/api/forms/experience/command`.

[Forms page authorization](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/forms/pages/forms-page.ts#L80) restricts non-fill screens to admins. Fill uses the signed-in subject/assignment or a valid share grant, enforces CSRF on POST, and [Respondent operation allowlist](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/forms/pages/forms-page.ts#L693) forwards only `RESPONDENT_DRAFT_SAVE` or `SUBMIT` from the guest-capable fill screen. Management operations cannot be smuggled through that route using the server's application credentials.

[Form and version contracts](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/forms/types.ts#L3) models stable question IDs/names, required flags, options and custom answers; forms expose drafts, versions and `currentVersionId`, and assignments carry `versionId`. [Builder catalogue and publishing controls](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/forms/views/forms.tsx#L46) supplies short/long text, date, number, dropdown, radio and checkbox labels. Publishing is unavailable before an initial save or while changes are dirty. This is a concrete UI/client candidate, not proof of the provider's storage, version immutability, share revocation, upload rules or full validation catalogue. The provider implementation was not among the three requested repositories.

## Stackpress auth/account styling — G-04 / G-05 / Q-014 / Q-015

[Auth and account view overrides](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/app/plugin.ts#L28) keeps Stackpress session handlers and maps branded GET/POST views at priority -50 for account, update, security, export, remove, password, 2FA and 2FA removal. It separately brands email/username/OTP/TOTP sign-in and records successful factor verification. This is a concrete example for reusing built-in behavior while styling its views. It uses the Stackpress view/provider composition; adapting it to this KB's single Ingest/Reactus rendering owner still requires P-01.

[Password recovery consumption](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/personnel-account/domain/recovery.ts#L159) validates a newest, pending, unexpired token for an active account, changes that account's auth secret, marks the token consumed and records the request/audit. It is password recovery, not a verified lost-authenticator reset flow. [Sensitive-account authorization](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/personnel-account/domain/session-security.ts#L17) requires admin role, CSRF for writes and an active verified 2FA row for the protected admin path. A stored factor's existence alone is not a fresh reauthentication proof.

[Branded account deletion view](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/app/views/auth-account/remove.tsx#L27) describes removing all sign-in methods and signing out, submits the vendor `confirmed`/`secret` fields and preserves CSRF. The wrapper does not implement or prove current-app data purge or cross-app erasure; the imported vendor handler was not executed or inspected from a newly installed dependency. This runtime label alone cannot establish Q-015. The later D-22 evidence resolution instead uses the already accepted kit/design scope, leaving this handler’s actual data coverage unproved.

## Shell, agent configuration and dependency adaptation

[Navigation drawer focus lifecycle](https://github.com/officepress/operations-resourcing/blob/75523ff3a6b141c5a46054a9b469bd4f8a6045a6/plugins/workspace/views/workspace-shell.tsx#L200) uses a 991.98px narrow breakpoint, traps Tab while its drawer is open, handles Escape, restores focus and temporarily locks body scrolling.
