# AGENTS.md — OfficePress UI Kit

Instructions for AI coding agents (Claude Code, Codex, Cursor, Copilot, …). Humans: see `README.md`.

This kit is the code form of the OfficePress design system: vanilla HTML/CSS/JS, no build step, no dependencies. The canvas file `officepress.pen` is the design source of truth; this kit mirrors it, and `reference/` holds snapshots of it. **Compose from the kit; never restyle it.**

Paths are relative to this file. In an app, the kit is vendored at `officepress/` — prefix paths with `officepress/`.

## Rules (the short version — details in `docs/guidelines.md`)

1. **Start from a template** (`docs/patterns.md`). Keep the frame: `.op-app` › `.op-aside` + `.op-main` › `.op-header` + `.op-body` › `main.op-content` + `.op-agent`. Change only nav items, title, header actions and `<main>`.
2. **Header globals are fixed:** notifications · agent · theme · user — copy `.op-globals` and its popovers verbatim.
3. **One family per app:** `css/officepress.css` then exactly one `css/families/<family>.css`. Mode = `data-mode` on `<html>` (no-flash head script from any template).
4. **Colours are tokens only** — `var(--op-*)`. No hex/rgb/hsl/named colours, no `[data-mode="dark"]` rules in apps. Links `--op-accent-text`; primary fills `--op-accent-strong`; unread is always `--op-dot` (green).
5. **Scales:** type 11/12/13/16/20 (28 on auth only), weights 400/700; spacing multiples of 4 (`--op-space-*`); radii 4/8/12/16/full, concentric (outer = inner + padding).
6. **Classes:** only `op-` classes that exist in `css/officepress.css`. Own classes: `app-…` in `app.css`, tokens only. State via ARIA/data attributes, not classes.
7. **Icons:** Lucide only — `<svg class="op-icon" aria-hidden="true"><use href="#i-NAME"/></svg>`, name in `icons/icons.json`. Icon-only controls need `aria-label`. No emoji.
8. **Restraint:** one primary button per region; `.op-section` for groups (not cards in cards); kit shadows for elevation; no gradients or new animations.
9. **Exceptions** need a reason at the spot: `/* op-allow: reason */` (CSS) or `data-op-allow="reason"` (HTML).
10. **Don't edit the kit from an app.** Missing component → build it in `app.css`, mention it as a kit candidate.

## Validate before you say you're done

```bash
python3 scripts/check.py <files-or-folder>      # in an app: python3 officepress/scripts/check.py .
python3 scripts/check.py --kit                  # kit maintainers: templates + index
```

0 errors is required (exit code 1 otherwise). Then follow `docs/workflows/review.md`: if you can open a browser, check `?mode=dark`, `?family=<other>`, `?aside=collapsed`, `?agent=open`, `?open=pop-user` and a 390 px width. If you can't, say so.

Environment: Python 3.9+ standard library only. No Node, no package manager required. Pages work from `file://`.

## Workflows

- New app → `docs/workflows/new-app.md` (`python3 scripts/new_app.py --name "X" --family operate --out ../x`)
- New screen → `docs/workflows/new-screen.md`
- Review → `docs/workflows/review.md`
- Themes, app CSS, tokens → `docs/workflows/theming.md`
- Add an icon → `python3 scripts/build_icons.py --add <lucide-name>`

## Kit maintainers

- Change the canvas first, then CSS, then `tokens/tokens.json`; keep contrast ≥ 4.5:1 for text in all 8 family × mode combinations.
- After changing components: update `docs/components.md`, the affected templates, and run `python3 scripts/check.py --kit` and `python3 scripts/check.py css`.
- Every value in `css/officepress.css` is on the scales; deliberate exceptions carry `/* op-allow */`.
