Authority: the user's 2026-11-13 brief, preserved verbatim as Raw Source in [the project brief](../resources/prompts/2026-11-13-app-forge-project-brief.md), plus the repository README line "A desktop container for productivity software" (git `a13d085`, remote `https://github.com/officepress/app-forge.git`). ## Accepted direction

- App Forge is a desktop app shell: a container in which users download and install apps from a marketplace without leaving the shell.
- Active apps appear on a left panel, and users toggle between them there.
- The starting apps are Rust ports of four existing OfficePress Create-family apps: Graphics, Designs, UIUX and Context.
- All four are human + agent tools. They share the same three kinds of settings: provider, skills and context. The user wants those settings configured once in the app shell instead of separately in each app.
- The shell and the ports use Stackpress Rust 0.2.x; see [Stackpress Rust foundation](stackpress-rust.md). App Forge is an OfficePress application and follows [OfficePress brand identity and logos](brand.md).

## Observed today: the shared settings in the current apps

- **Providers** are the agent CLIs on the machine: Claude, Codex, OpenCode and Pi. Each app probes availability, version, path and models, records which ones the person switched on, and compares versions against a tested baseline. Graphics runs all four (Claude through the Agent SDK, CLI providers through an MCP bridge with one-shot turns and no session resume); Context detects all four but only Claude runs work today. Sources: `create-graphics/server/providers.ts`, `create-context/server/core/providers.ts`.
- **Skills** are a library of instruction documents (SKILL.md folders or plain markdown) imported from a local folder or a GitHub repo, stored under the app's state folder, that the agent takes along. Source: `create-graphics/server/skills.ts`, a compact take on UIUX's SkillLibrary.
- **Contexts** are knowledge contexts the agent reads. Graphics has a Settings › Contexts screen (`src/screens/SettingsContexts.tsx`); UIUX shows selected knowledge contexts as removable chips in project chat and saves them with the next message; Context produces `.agents` knowledge bases.
- Each app keeps its own state folder today (for example `~/Library/Application Support/create-graphics/state`), so these settings are duplicated per app. The shell is meant to own them.

These observations locate current behavior; the exact shared-settings contract for the shell is spec work (Gap G-06).

## Verified foundation (slice 1, 2026-11-13)

Promoted from spec 00001 after its tasks were verified. These describe the repository as built; the spec holds the sequencing and evidence.

- The repository is a Cargo workspace of five crates: `forge-contracts` (client-safe DTOs, the fixed operation allowlist, the placeholder catalogue), `forge-host` (Stackpress plugins `shell-state`, `catalog`, `apps`, `settings`, `providers` and the `NativeHost` adapter), `forge-ui` (one Leptos root: rail, Home, App Store, Settings, app placeholder), `forge-client` (WASM CSR entry and IPC bridge) and `forge-app` (Tauri host, one command `forge_invoke`). Workspace lints mirror Stackpress: `unsafe_code` forbid, `missing_docs` deny, no unwrap/expect/panic in library code.
- Dependencies are the crates.io releases `stackpress-lib`, `stackpress-server`, `stackpress-leptos` 0.2.0, `leptos` 0.8.22, `wasm-bindgen` 0.2.129, `tauri` 2.12.5 and `tauri-build` 2.7.4. Rust 1.96, the `wasm32-unknown-unknown` target and the `wasm-bindgen` 0.2.129 CLI are required.
- Build order: `python3 -I scripts/make-icon.py` once (icons from the suite mark), `python3 -I scripts/build-client.py` (writes `dist/csr`, which Tauri embeds at compile time), then `cargo build -p forge-app` or `cargo run -p forge-app`.
- Shell state lives in Tauri's app config directory for identifier `ph.officepress.app-forge` (on macOS `~/Library/Application Support/ph.officepress.app-forge/`) as `settings.json` and `installed.json`, revision 1, written atomically.
- The UI reaches the host only through `forge_invoke(operation, json)`; the host admits the main window, the fixed operation names, JSON objects up to 256 KiB and at most 16 in-flight calls, with a 20-second deadline. Public rejections come back as Stackpress envelopes, not bridge errors.
- Without `window.__TAURI__` the same client bundle runs a browser preview backed by memory (nothing saved), and `#store`, `#settings` or `#app/<id>` select the first screen. Serve `dist/csr` through devmetrics and capture with headless Chrome for review images; screen capture of the native window is not available from agent sessions on this machine.
- Proof P-01: the Tauri window hosted the Leptos CSR root and invoked the in-process Stackpress host on macOS. Bundling, signing and Finder-launch PATH behaviour are not yet verified.
- Slice 2 (user review): the UI follows the OfficePress Create-family shell as the UIUX app wears it (its dark tokens verbatim, a derived light palette), implemented with plain Leptos elements rather than Stackpress Leptos components; where Stackpress Leptos fits in the UI is deferred by the user. The left panel has no brand block, resizes by dragging (56 to 420 px, stored in settings) and shows icons with hover tooltips below 140 px. Settings is its own page with the UIUX layout; its menu is Back to app · General · Providers, Skills, Contexts · App Store, separated by dividers, and the left panel offers only the installed apps and Settings (the App Store lives in Settings). General shows the app name, description, version, an update-check provision (target: the OfficePress GitHub Releases convention) and the bundled `CHANGELOG.md`. The theme always follows the operating system; there is no toggle, and the document body and native window are painted in the scheme's canvas colour so no light frame appears.
- Shared settings libraries are ports of the UIUX app's: providers (probe, tested-version comparison, switches that refuse a missing tool), skills (`<state>/skills/<id>/` plus `skills.json`; imports from a folder, GitHub or skills.sh by shallow git clone), contexts (`contexts.json` plus owner-only `context-secrets.json`; stdio, streamable HTTP and folder transports; folder and stdio checks work, HTTP checks do not yet). The native folder chooser uses macOS `osascript`.
- The packaged window's CSP attaches nonces to inline `<style>` elements found in the page, which makes browsers ignore `'unsafe-inline'`; runtime-injected `<style>` elements and `style` attributes are then blocked. The shell therefore serves its stylesheet as `forge.css` and sets dynamic styles through the CSSOM (`style:width`), never through inline style markup. The browser preview does not enforce this, so it cannot catch the regression; a desktop screenshot can.
- Settings reads ignore fields written by earlier builds so an existing `settings.json` never blocks startup. In debug builds the client reports startup failures to the host log as a `client-failure:` operation name.

## Verified foundation (slice 3: app packages, 2026-11-13)

Promoted from spec 00002 after Proof P-02 passed. The spec holds the decisions (B-01 to B-10), the Gaps B-G1 to B-G6 and the launch log.

- Apps are packages: a zip with `forge.json` at its root (`id`, `name`, `description`, `family`, `version`, `api`, `backend.entry` and `args`, `ui.entry`, optional `mark`, `permissions`), a backend executable and a UI bundle. The catalogue entry names `package.url` (`https://`, `http://` or `file://`) and `package.sha256`; the installer refuses a checksum or manifest mismatch before anything is unpacked. A `catalog.json` in the state directory adds or overrides catalogue entries for development. Publisher signing is open (spec 00002 Gap B-G1).
- Installs live at `<state>/apps/<id>/<version>/`, recorded in `installed.json` with the package's version, `api`, `ui_entry` and `backend_entry`; each app's own data lives in `<state>/app-data/<id>/`, passed to the backend as `FORGE_STATE_DIR` and `app/storage`. The shell's `PROTOCOL_VERSION` is 1 and a package's `api` must not exceed it.
- The backend runs as a child process speaking JSON-RPC 2.0, one message per line, over its stdin and stdout, both directions. The shell sends `app/initialize` (10-second deadline) and `app/shutdown`; `settings/changed` is defined but not yet sent (B-G6). The app asks `providers/list`, `skills/list`, `contexts/list` and `app/storage`, answered by the shell's own capabilities. Every other method is the app's own and is relayed from its UI through `apps-call` (20-second deadline). Uninstall stops the backend first; closing the shell kills every backend.
- `forge-sdk` is the only crate an app depends on: manifest, protocol constants, the JSON-RPC peer, `serve` for the backend and `forge-sdk.js` for the UI. `examples/hello-app` is the smallest complete package; `scripts/build-hello-package.py` builds and zips it and writes a `file://` catalogue. `forgectl` (a binary in `forge-host`) lists, installs, uninstalls, starts and calls packages against a state directory.
- The Tauri window serves `forge-app://localhost/<id>/<path>` from the install folder (canonical-path checked, MIME by extension, `Access-Control-Allow-Origin: *`), and the app screen hosts the UI entry in a sandboxed iframe (`allow-scripts allow-same-origin allow-forms allow-modals`) once `apps-start` has returned. The page's `forge-sdk.js` posts `forge:rpc` messages that the shell relays and answers with `forge:rpc:result`. All packages share one origin for now (B-G2).
- WebKit asks the window's navigation policy for subframe loads too: a `forge-app://` frame the policy does not admit is cancelled silently, with no CSP report and no request to the scheme handler. The policy therefore admits exactly the shell origin and the package origin (no port, nothing remote).
- The supervisor treats a start in progress as a state: a repeat start, a call or a stop during it waits for the start to end rather than launching twice or refusing. The UI mounts the frame only after the host confirms the start, because the hello frame's first call once arrived before the backend was registered.
- Debugging the packaged window, which has no console: debug builds print admitted operation names, `scheme request` lines and `client-trace:` lines (bridge relay and reply, frame load, a startup probe of the package scheme, `securitypolicyviolation` reports) to stderr, and `FORGE_START_HASH='#app/hello'` opens a screen directly. Touch `crates/forge-app/tauri.conf.json` after rebuilding the client so Tauri re-embeds `dist/csr`.

## Verified foundation (slice 4: agent runtime, 2026-11-13)

Promoted from spec 00003 after Proof P-03 passed on all four providers. The spec holds the decisions (C-01 to C-12), the Gaps C-G1 to C-G10 and the run logs.

- The shell is the agent host. A packaged app's backend sends `agent/run` (SDK `ShellClient::run_agent`) with a prompt, optional `tools` of its own, `native_tools`, `cwd`, `read_dirs`, `images`, `effort`, `model`, `output_schema`, `session`, and the `skills` and `contexts` to attach (absent means all skills and all enabled contexts). The shell picks an enabled, installed provider (the requested one, else the first in Claude, Codex, OpenCode, Pi order), and answers `{ run, provider }` once the CLI started. `agent/cancel { run }` interrupts the provider (SIGINT, then kill after 5 seconds).
- Events come back as `agent/event` notifications in one vocabulary for every provider: `started {provider, session?}`, `text {delta}`, `thinking {delta}`, `tool_call {id, name, input}`, `tool_result {id, output, is_error}`, `status {message}`, `finished {text, session?, usage?}`, `failed {message, cancelled}`; exactly one terminal event per run. The app's own tool calls are reported by the bridge; provider-native tool activity passes through from the stream.
- The app's tools reach CLIs through MCP: the shell registers `forgectl mcp-bridge --socket <path> --run <id>` (Claude `--mcp-config` plus `--strict-mcp-config`, Codex `mcp_servers.forge.*` with `required=true` and `default_tools_approval_mode="approve"`, OpenCode `mcp.forge` in a generated config). The bridge connects to an owner-only Unix socket `<state>/agent-runs/bridge-<pid>.sock` and speaks the SDK's newline JSON-RPC (`bridge/tools`, `bridge/call`) with the run id and a per-run token carried in its environment. Pi has no MCP and loads a generated extension that registers the same tools over the same socket. The bridge program is `forgectl` beside the running executable, or `FORGE_BRIDGE_BIN`. Tool results are text only (Gap C-G7).
- Each provider is launched unattended the way the Create apps launch it at the same CLI versions (spec 00003 decision C-05): Claude Code `-p --output-format stream-json --include-partial-messages --input-format stream-json --permission-mode dontAsk --permission-prompts none` with the message on stdin and `CLAUDECODE`/`CLAUDE_CODE_ENTRYPOINT` removed; Codex `exec --json -c approval_policy="never" -c sandbox_mode="read-only"` with the prompt on stdin; OpenCode `run --format json --agent forge` with `OPENCODE_CONFIG`; Pi `-p --mode json --no-session --no-builtin-tools -e <extension>`. Skills and folder contexts travel as text in the system prompt (16,000 characters per document); MCP contexts are added to Claude, Codex and OpenCode configurations with their secrets.
- Run folders live at `<state>/agent-runs/<run>/` (`system.md`, generated configs, images, `work/`, the provider's raw `events.jsonl`), owner-only, removed when the run ends unless `FORGE_KEEP_RUNS` is set. Runs are concurrent and may last 30 minutes. Codex only calls an offered tool when the prompt makes it necessary; OpenCode's default model on this machine refuses tool use, so a tool-capable model must be named (C-G10).
- Backends push events to their own UI frame with `ui/event` (SDK `ShellClient::emit`), delivered as `forge:event` messages that `on(method, handler)` in `forge-sdk.js` receives; the path is supervisor broadcast, Tauri window event `forge:app-event` (capability `core:event:allow-listen`), shell bridge, `postMessage` into the frame marked `data-app`. Running backends receive `settings/changed { kind }` when providers, skills or contexts change.
- The App Store catalogue merges three sources by id: the bundled starting list, the hosted `catalog.json` fetched from a GitHub Release (`CATALOG_URL`, overridable with `FORGE_CATALOG_URL`, cached in `catalog-remote.json` for a day, refreshed on listing or with `refresh: true`), and the local `catalog.json` override. Hosted packages must carry an ed25519 `signature` by a publisher the shell trusts: the bundled OfficePress key (public half `60bc161e...cb1266` in `PUBLISHERS`; the secret half is the user's, generated 2026-11-13 with `forgectl keygen`, kept outside the repository) plus `FORGE_TRUSTED_KEYS` for development; override entries may be unsigned. `forgectl sign --key FILE ARCHIVE` prints the signature a catalogue entry needs, and `scripts/build-hello-package.py` signs when `FORGE_SIGNING_KEY` names the key file. The hosted URL is the compiled default until rollout, when the user will choose the public home (it may become a Settings field); until then the fetch fails quietly and the bundled and override sources answer.
- `forgectl run [--provider P] [--model M] PROMPT` runs one turn from a terminal with a `clock` tool and prints the events as JSON lines; it is the fastest check that a provider works on a machine.
- First port: Graphics, then Context, per the sizing record ([Create apps: agent plumbing sizing and runtime needs](../references/00012-create-apps-agent-plumbing-sizing.md)).

## Verified foundation (slice 5: the Graphics port, 2026-11-13)

- The editor reproduces the source app's store (whole-document snapshots 60 deep, pixel maps included), its sixteen tools, keyboard map, panels and dialogs. Leptos reactive closures must be `Send`, so browser objects live in `StoredValue<_, LocalStorage>`.

Chat entries and provider sessions save into `chat.json`.
- Review outside the shell: `scripts/preview-graphics.py <file.opng>...` stages the UI with `harness.html`, which plays the backend in the same page (outside an iframe `window.parent` is the page), and dumped open replies from `graphics-app --dump`; serve the folder and capture with headless Chrome. Unattended desktop checks: `GRAPHICS_AUTO_ASK='<prompt>' FORGE_START_HASH='#app/graphics'` opens a default document and runs one turn.
- The prompt is one shared composer (`components/composer.rs`, pure parts in `picks.rs`) on the home screen and in the chat panel: chips for images, skills, contexts and notes, the + menu, the agents popover (one agent until teams arrive), and the two-level provider, model and effort picker remembered in local storage as `graphics-pick`. The icon family is the source app's Lucide-compatible stroke set in `iconset.rs` (67 icons, `currentColor`, decorative with the accessible name on the control); never use Unicode glyphs as icons. Harness flags: `&home`, `&chat`, `?icons`.
- Next slice candidates recorded as Gaps: multi-agent modes, model lists from the shell, effect drag reordering, panel resizing, the system clipboard, native dialogs beyond macOS.

## Verified foundation (slice 6: the Designs port, 2026-11-14)

Promoted from spec 00005 after Proofs P-08 to P-10 passed. The spec holds the decisions (D-01 to D-08), the Gaps (D-G1 to D-G12), the journeys and the evidence; the source app's behaviour is recorded in four Reference Files ([data model and file formats](../references/00016-create-designs-dossier-model-and-formats.md), [engine and editor](../references/00017-create-designs-dossier-engine-and-editor.md), [UI inventory and endpoints](../references/00018-create-designs-dossier-ui-and-agent.md), [agent contract](../references/00026-create-designs-dossier-agent.md)).

- The second package is the Rust port of OfficePress Designs, under `apps/designs/`: `designs-model` (the document as ordered JSON, the formats, instance expansion, variables, the layout engine, validation, operations and hand edits; native and wasm), `designs-app` (the backend on `forge-sdk` and `forge-app-kit`) and `designs-ui` (Leptos CSR to WebAssembly on `forge-ui-kit`). `scripts/build-designs-package.py` builds and zips it with its bundled assets; `scripts/sync-designs-assets.py` copies the guides, styles (archetypes parsed by `scripts/designs-archetypes.mjs`), kits, craft skills and lucide glyphs from the source checkout into `apps/designs/assets/`, which is committed so the package never depends on the checkout.
- Two kits were extracted from Graphics so the Create apps share one composer and one agent runtime: `forge-ui-kit` (wasm: `AgentUi`, the subscriptions, `ChatPanel`, `Composer`, the icon family in `iconset.rs`, `kit.css`) and `forge-app-kit` (native: `AgentApp` for an app's prompts, tools and labels; `AgentState` runs the turn, relays tool calls as `<prefix>/command` events with a 60-second deadline, keeps the chat and sessions, and emits `<prefix>/chat|status|streaming|session|cursor|settings`). An app implements `compose`, `tools`, `tool_label`, optionally `tool_call` (answer locally or relay) and `relayed_result`.
